# ModrinthProxy

Веб-интерфейс для Modrinth на русском языке. Простой доступ к модам, плагинам, шейдерам и другому контенту для Minecraft без VPN и лишних заморочек.

Все файлы качаются напрямую с CDN Modrinth. Мы не храним моды у себя - только делаем удобный интерфейс и кэшируем описания.

**Сайт:** https://modrinth.black/

## О проекте

Modrinth - один из лучших сайтов для модов Minecraft, но в России к нему хреновый доступ. Этот проект решает проблему - работает через их публичный API, показывает весь контент на русском, фильтрует то что надо по закону.

**Как работает:**
- Вы открываете сайт и ищете мод
- Мы запрашиваем инфу через Modrinth API v3
- Показываем описание, версии, скриншоты
- Файлы качаются напрямую с cdn.modrinth.com
- Ничего не храним у себя, только кэшируем метаданные (от 3 часов до 7 дней в зависимости от типа данных)

**Почему это легально:**
- Используем публичный API Modrinth (никаких парсеров)
- Файлы идут с их CDN, мы их не трогаем
- Фильтруем контент по требованиям РКН через JSON blacklist'ы
- Open source, всё прозрачно

## Что умеет

- Полный каталог Modrinth - моды, плагины, шейдеры, ресурспаки, датапаки, модпаки
- Поиск с фильтрами по версиям Minecraft, загрузчикам (Fabric/Forge/NeoForge/Quilt), категориям
- Работает на телефонах и планшетах
- Весь интерфейс на русском
- Автоматическая фильтрация запрещённого контента (РКН blacklist)
- Агрессивное кэширование - не нагружаем API Modrinth лишний раз

### Что нужно

- **Node.js 20 или новее** (подойдёт любая LTS-версия: 20, 22, 24). На Windows 7/8 современный Node.js не ставится — нужна Windows 10 или новее.
- Больше ничего. Отдельный сервер базы данных **не нужен**.

### База данных

Сайт хранит аккаунты, избранное, лайки, историю скачиваний и настройки в **SQLite** — это обычный файл на диске.

- При первом запуске файл `data/site.db` создаётся **сам**, вместе с папкой `data/` и всеми таблицами. Ничего настраивать и импортировать не нужно.
- При обновлении проекта новые таблицы и колонки тоже добавляются сами при запуске (миграции в `lib/db.js`). Ваши данные при этом сохраняются.
- Папка `data/` не попадает в git — у каждой копии сайта своя база.
- **Бэкап** — просто скопируйте папку `data/` (лучше при остановленном сайте).
- **Начать с чистого листа** — остановите сайт и удалите папку `data/`. При следующем запуске создастся новая пустая база.
- Хотите хранить базу в другом месте — укажите путь в переменной `DATABASE_FILE` (см. «Необязательные настройки» в спойлере «Для профи»).

Каталог модов, плагинов и прочего в базе не хранится — он всегда берётся из Modrinth API, поэтому сразу после запуска сайт показывает весь контент.

### Быстрый старт

```bash
git clone https://github.com/b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0/modrinth-proxy.git

npm install
npm run dev
```

### Запуск на своём сервере

`npm run dev` — режим разработки: он медленнее и пересобирает страницы на лету. Для постоянной работы соберите сайт и запустите его в обычном режиме:

```bash
npm install
npm run build
npm start
```

По умолчанию сайт слушает порт 3000. Другой порт можно задать так: `npm start -- -p 8080`.

Важно:
- **Нужен постоянный диск.** База — это файл в `data/`, поэтому сайт должен работать на обычном сервере или VPS, где файлы не пропадают между перезапусками. Бесплатные serverless-хостинги вроде Vercel, Netlify и Cloudflare Pages для этого **не подходят**: каталог там откроется, но аккаунты, избранное и лайки работать не будут.
- **Запускайте один процесс сайта.** Несколько процессов на одну базу (например, cluster-режим pm2) могут помешать друг другу при обновлении базы.
- Чтобы сайт поднимался сам после перезагрузки сервера, используйте менеджер процессов, например `pm2 start npm --name modrinth-proxy -- start` или systemd.
- Если перед сайтом стоит nginx или другой прокси, проверьте `TRUSTED_PROXY_HOPS` (см. ниже) — от него зависит, как сайт определяет IP посетителя для защиты от спама.
- После обновления кода из git снова выполните `npm install` и `npm run build` — в проекте могут появиться новые пакеты.

### Необязательные настройки

Сайт полностью работает без них. Если нужно — создайте в корне проекта файл `.env.local` и впишите нужные строки:

```bash
# Путь к файлу базы (по умолчанию data/site.db)
DATABASE_FILE=/var/lib/modrinth-proxy/site.db

# Вход через GitHub. Создайте OAuth App на github.com/settings/developers,
# в поле Authorization callback URL укажите https://ваш-домен/api/auth/github/callback
GITHUB_OAUTH_CLIENT_ID=
GITHUB_OAUTH_CLIENT_SECRET=

# Токен GitHub для страницы новостей сайта (она собирается из коммитов репозитория) —
# без него действует маленький лимит запросов к GitHub API
GITHUB_TOKEN=

# Вход через Telegram и уведомления об обновлениях в Telegram.
# Токен выдаёт @BotFather; для входа через виджет боту нужно указать домен сайта (/setdomain),
# поэтому на localhost вход через Telegram не заработает
TELEGRAM_BOT_TOKEN=

# Сколько прокси перед сайтом дописывают адрес в X-Forwarded-For.
# По умолчанию 2 (например, Cloudflare + nginx). Если перед сайтом только nginx — поставьте 1
TRUSTED_PROXY_HOPS=2
```

Без ключей GitHub и Telegram соответствующие кнопки входа просто не показываются.

### Если что-то не запускается

- **`npm install` падает на `better-sqlite3`** — обычно это слишком старая или слишком новая «нечётная» версия Node.js. Поставьте актуальную LTS-версию и повторите `npm install`.
- **Порт 3000 занят** — запустите на другом порту: `npm run dev -- -p 3001`.
- **Ошибка доступа к `data/`** — у пользователя, от которого запущен сайт, должны быть права на запись в папку проекта (или в папку из `DATABASE_FILE`).

## Особенности реализации

### Фильтрация контента

Сайт блокирует контент через систему блокировок.

**Структура блокировок:**

Все блокировки хранятся в JSON файлах в директории `lib/blacklist/`:
- `projects-servers.json` - заблокированные серверы
- `projects-mods.json` - заблокированные моды
- `projects-resourcepacks.json` - заблокированные ресурспаки  
- `projects-datapacks.json` - заблокированные датапаки
- `projects-modpacks.json` - заблокированные модпаки
- `organizations.json` - заблокированные организации
- `users.json` - заблокированные пользователи (по ID)
- `username-patterns.json` - ники и ID, для которых вместо username показывается ID пользователя (профиль и моды остаются)
- `url-patterns.json` - заблокированные URL паттерны (изображения в описаниях)
- `avatar-patterns.json` - заблокированные паттерны аватарок (замена на `/icon.png`)
- `words.json` - заблокированные слова

**Добавление в блокировку:**

Просто отредактируйте соответствующий JSON файл.

**Проекты (по slug или ID):**
```json
[
  "project-slug-1",
  "a1B2c3D4"
]
```
Вы можете добавлять как текстовые псевдонимы (slug), так и уникальные неизменяемые ID проектов (например, `a1B2c3D4`), чтобы блокировка продолжала действовать даже после изменения адреса/названия проекта.

**Пользователи (по ID) — полная блокировка профиля:**
```json
[
  "xzTIfqot"
]
```

**Маскировка ника — моды и профиль остаются, вместо ника везде ID:**
```json
[
  "forbidden-nick",
  "a1B2c3D4"
]
```
В `username-patterns.json` можно указать ник (точное совпадение, без учёта регистра) и/или ID. Пользователь не банится: ссылки `/user/{id}` работают, в UI отображается только ID.

Заблокированный контент:
- Не отображается в результатах поиска
- Показывается счетчик заблокированных элементов
- При попытке прямого доступа показывается страница с уведомлением
- Автоматически фильтруется на всех страницах сайта
- Заблокированные пользователи показывают страницу РКН вместо профиля
- Проекты заблокированных пользователей не отображаются в их профилях
- Заблокированные изображения заменяются на красивую плашку с уведомлением
- Заблокированные аватарки заменяются на дефолтную иконку сайта (`/icon.png`)
- Замаскированные ники отображаются как ID (см. `username-patterns.json`)

### Кеширование

API запросы кешируются через встроенную систему Next.js (`revalidate`):
- Minecraft-серверы: 180 секунд (3 минуты)
- Поиск проектов: 10800 секунд (3 часа)
- Детали проектов / модов: 60 секунд (1 минута)
- Версии проектов: 21600 секунд (6 часов)
- Детали версии: 21600 секунд (6 часов)
- Команда проекта: 86400 секунд (24 часа)
- Пользователи: 43200 секунд (12 часов)
- Версии Minecraft: 86400 секунд (24 часа)
- Категории: 604800 секунд (7 дней)
- Подсчёт проектов на главной: 86400 секунд (24 часа)
